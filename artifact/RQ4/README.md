# RQ4: Equivalence Mapping Effectiveness

Evaluates RosdepAuditor's effectiveness in identifying equivalent packages across repositories.

## Files

### Scripts
- `run_distribution_comparison.py` - Runs experiments comparing RosdepAuditor's detector, LLM detectors, and non-LLM baselines
- `build_ground_truth.py` - Builds the ground-truth dataset from scratch via GitHub Search API and filters to ubuntu-noble-mapped entries with ≥2 repos
- `RQ4_plot.py` - Generates publication-quality w-sensitivity figure from comparison results
- `verify_all_llms.py` - Verifies LLM results and generates validation statistics

### Usage

#### Method names used below

| Name | Meaning | Output location |
| --- | --- | --- |
| `detector` | RosdepAuditor's `PackageDistributionDetector`. It starts from a baseline package, usually the `ubuntu_noble` package in the ground-truth entry, and predicts equivalent packages for the other configured repositories. | `../data/result/detector_w00/` through `../data/result/detector_w10/` |
| `mapper` | Repology-based baseline (`RepologyMapper`). | `../data/result/mapper/` |
| `rosdep_ci` | Rosdep CI baseline (`RosdepCIMapper`). | `../data/result/rosdep_ci/` |
| `llm_*` | LLM detector runs for configured model presets. Preset names are filesystem-friendly, e.g., `claude-opus-4-5` corresponds to the paper's Claude-Opus-4.5 model. | `../data/result/llm_*/` |

Each per-entry result is a JSON file named after the rosdep key. The generated
markdown report compares those JSON outputs with
`../data/ground_truth_dataset_filtered.yaml` and reports exact, partial, and no
matches across the 854 platform instances.

#### build_ground_truth.py
```bash
cd artifact/RQ4/scripts

# Build ground_truth_dataset.yaml from scratch (API mode)
python build_ground_truth.py --build

# Filter existing dataset to ubuntu-noble-mapped entries with ≥2 repos
python build_ground_truth.py --filter

# Build + filter in one go
python build_ground_truth.py --all
```

The `--build` command searches GitHub for merged rosdep PRs created after
`2025-05-01` and merged before `2025-09-30`, extracts the modified rosdep keys from each
PR diff, and merges the post-PR content into
`ground_truth_dataset.yaml`.  A `GITHUB_TOKEN` environment variable is required
for GitHub API access.

The `--filter` command loads the full dataset and keeps only entries that are
mapped to `ubuntu_noble` **and** span at least two distinct repository
platforms, producing `ground_truth_dataset_filtered.yaml`
(112 entries / 854 platform instances).

#### run_distribution_comparison.py
```bash
cd artifact/RQ4/scripts

# Detector mode: compare RosdepAuditor under different w values
# Default weights are 0.0, 0.1, ..., 1.0; cached detector_w* JSON files are reused unless --force is set.
python run_distribution_comparison.py --mode detector

# LLM mode (requires provider credentials and API access)
# Default presets are glm-4.7, deepseek-v3.2, gemini-3-pro, and claude-opus-4-5
# (reported in the paper as GLM-4.7, DeepSeek-V3.2, Gemini-3-Pro, and Claude-Opus-4.5).
python run_distribution_comparison.py --mode llm

# Baseline mode: refresh RepologyMapper and RosdepCIMapper outputs
python run_distribution_comparison.py --mode baseline

# Compare detector with Repology, RosdepCI, and LLM methods at w=0.7
python run_distribution_comparison.py --mode compare
```

All modes create a timestamped `../data/comparison_*.md` report and a YAML
summary under `../data/reports/`. `--mode compare` also writes combined
per-entry JSON files under `../data/result/combined/`; this is the source for
the packaged `../data/final_version.md`. `--mode detector` is the source for
the packaged `../data/w_related_ver.md`.

Use `--force` to rerun a method and overwrite/add per-entry JSON outputs.
Without `--force`, existing JSON files are loaded from `../data/result/`.
Forced detector and baseline runs may query live package indexes or Repology.
Forced LLM runs require provider credentials and can differ from the packaged
outputs because model services change over time.

#### verify_all_llms.py
```bash
cd artifact/RQ4/scripts

# Calculate extra (non-existent) statistics
python verify_all_llms.py --extra-nonexistent
```

This reads the packaged comparison outputs and writes verification JSON files
under `../data/verification_results/`, including
`extra_nonexistent_stats.json` and per-LLM nonexistent-package lists.

### Data
- `ground_truth_dataset.yaml` - Full ground-truth equivalence-mapping dataset (135 entries); can be rebuilt from scratch with `build_ground_truth.py --build`
- `ground_truth_dataset_filtered.yaml` - The filtered ground-truth dataset used for the reported 112-entry / 854-instance evaluation; generated by `build_ground_truth.py --filter`
- `final_version.md` - Packaged method-comparison report used for the paper's main RQ4 comparison table
- `w_related_ver.md` - Packaged weight-sensitivity report for `w=0.0` through `1.0`
- `w_sensitivity.pdf` - Publication figure derived from `w_related_ver.md`
- `overall_summary.json`, `package_count_summary.json` - Top-level packaged summary JSON files included alongside the markdown reports

### Raw Results (`result/`)
- `detector_w00/` through `detector_w10/` - Cached per-entry outputs for our detector under different weight settings
- `llm_*/`, `rosdep_ci/`, `mapper/` - Cached per-entry outputs for the LLM and baseline methods
- `combined/` - Combined per-entry comparison outputs reused by the packaged reports

### Verification Results (`verification_results/`)
- `verified_entries_summary.json` - Aggregated exact/partial/none verification statistics for all evaluated tools
- `extra_nonexistent_stats.json` - Extra-output and nonexistent-package statistics summarized from the packaged comparison results
- `{llm}_summary.json` - Per-LLM verification summaries
- `{llm}_fake_packages.json` - Lists of nonexistent or hallucinated packages produced by each LLM
- `comparison_summary.json` - Cross-tool package-count comparison derived from the cached per-entry outputs
- `overall_summary.json`, `package_count_summary.json` - Additional packaged verification summaries consumed by the analysis scripts
